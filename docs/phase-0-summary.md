## 3. 核心结论摘要

### 3.1 产品范围

- **本期做**：Web 平台，覆盖 8 个功能模块（M1-M8），48 项功能，其中 P0 首版必须 30 项
- **本期不做**（已明确排除并说明原因）：真实支付网关、真实 AI 品相识别、真实智能柜硬件、微信小程序、教务系统对接、短信外呼

### 3.2 技术栈（按你的指定）

```
前端：Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + Tailwind CSS
架构：Feature-Sliced Design（app / pages / widgets / features / entities / shared）
后端：Supabase（PostgreSQL + Auth + Storage + Edge Functions + RLS）
部署：前端国内云 + Nginx + CDN；后端 Docker 自托管 Supabase + 国内镜像加速
```

### 3.3 数据库

24 张表分 6 组，16 个枚举类型，共 68 条 RLS 策略（阶段 2 已落地）。
在你指定的 19 张表之外，**补充了 5 张业务必需表**（`order_items`、`rentals`、`donations`、`user_addresses`、`book_categories`），原因见 data-model.md 第 1 节。

见第 6 节。

## 4. 关键设计决策

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-01 | Supabase 而非自建后端 | 团队小，Auth/Storage/RLS 开箱可用 | 供应商绑定，国内需自托管 |
| ADR-02 | FSD 而非传统三层 | 8 模块纵切，改动收敛 | 学习成本，需 ESLint 强制边界 |
| ADR-03 | 定价逻辑放 Edge Function | 系数是商业机密 | 需网络往返 |
| ADR-04 | Storage 私有桶 + 签名 URL | 防图书照片被爬 | 需管理签名过期 |
| ADR-05 | 本期模拟支付 | 真实支付需牌照，法务未确认 | 上线前必须补 |
| ADR-06 | 碳系数与定价系数入库且强制带来源字段 | 落实计划书「不虚构数据」原则 | 后台需维护 |

## 5. 风险清单（按严重度排序）

| 级别 | 风险 | 影响 | 应对 |
|---|---|---|---|
| 🔴 高 | **真实支付未接入** | 无法真实交易，商业闭环不成立 | 上线前完成法务确认 + 持牌机构接入 |
| 🔴 高 | **版权合规** | 盗版教材流转 → 平台连带责任 | 三层风控已设计（ISBN 校验 / 人工复核 / 授权对接） |
| 🔴 高 | **RLS 配置错误** | 一张表漏开 RLS = 全表数据对全网开放 | 阶段 2 交付 RLS 测试脚本，CI 强制执行 |
| 🟠 中 | **示例数据被当作真实数据展示** | 虚假宣传风险 | 系统强制：示例数据必须打角标；系数必填来源 |
| 🟠 中 | **学生证等敏感个人信息** | 违反 PIPL，面临处罚 | 单独同意 + 加密存储 + 限定留存期 + PIPIA |
| 🟠 中 | 无微信小程序端 | 学生触达受限 | 需评估 uni-app/Taro 适配成本 |
| 🟡 低 | 东京区域延迟 | 体验略逊 | 实测后决定是否迁移国内云 |
| 🟡 低 | 技术债 7 条（TD-01 ~ TD-07） | 长期维护成本 | 每迭代预留 20% 工时偿还 |
