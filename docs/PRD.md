## 1. 产品定位

| 项目 | 内容 |
|---|---|
| 产品名称 | 青阅循环 |
| 一句话定位 | 校园二手图书智能循环与生态服务平台 |
| 宣传语 | 让闲置的书，再一次被需要 |
| 切入场景 | 高校教材与图书的周期性流转（毕业季集中供给、开学季集中需求） |
| 载体 | **Web 平台**（本站开发范围） |
| 规划载体 | 微信小程序 / 校园智能回收柜交互屏（本期不实现，仅预留接口） |

> ⚠️ **范围声明**：商业计划书原文以「微信小程序」为主要载体。本项目按你的要求实现为 **Web 平台**。
> 二者差异需在阶段 1 前确认：原生小程序不支持直接复用 Web 代码，若后续要上小程序需要额外适配层
> （uni-app / Taro）或独立开发。当前架构按 **Web 优先、接口留出复用空间** 设计。

## 2. 用户角色

| 角色 | 描述 | 核心诉求（引自计划书 2.4 节） |
|---|---|---|
| 学生（卖方） | 毕业生、转专业学生、课程结束后的学生 | 图书多且重、发布麻烦、废纸回收价低；希望省事、透明、快速处理 |
| 学生（买方） | 低年级学生、考研考证用户 | 新书贵、同专业二手书难找、信息分散；希望便宜、就近、精准 |
| 校园大使 | 勤工助学学生、社团成员 | 希望有可量化的推广工具与收益记录 |
| 运营人员 | 平台运营、质检、仓储 | 需要后台管理库存、订单、质检分级与数据分析 |
| 学校方 | 团委、后勤、图书馆、学院 | 毕业季回收组织成本高；需要可展示的绿色校园数据 |
| 合作企业 | 环保、文具、教育服务品牌 | 需要可验证的循环经济场景与 ESG 数据 |
| 公益机构 | 图书捐赠与公益阅读项目 | 需要捐赠流向可追溯 |

## 3. 核心业务闭环

```
        ┌──────────────── 供给端（学生卖书）────────────────┐
        │  发布 / 预约上门 / 投回收点 / 投智能柜              │
        └───────────────────────┬──────────────────────────┘
                                ▼
                   ┌────────────────────────┐
                   │  ISBN 识别 + 品相评估    │  ← AI 视觉识别（本期为占位接口）
                   │  动态定价引擎            │
                   └───────────┬────────────┘
                               ▼
        ┌──────────────── 平台中枢 ────────────────┐
        │  质检分级 → 入库上架 → 供需匹配 → 履约交付  │
        └───────────────────────┬──────────────────┘
                                ▼
        ┌──────────────── 需求端（学生买书）────────────────┐
        │  出售 · 以书换书 · 租赁 · 公益捐赠                 │
        └───────────────────────┬──────────────────────────┘
                                ▼
        ┌──────────────── 沉淀与反哺 ────────────────┐
        │  碳账户 / 积分  ·  供需数据库  ·  运营看板    │
        │  数据反哺：需求预测 → 动态定价 → 智能匹配      │
        └───────────────────────────────────────────┘
```

## 5. 动态定价模型

计划书 3.2 节给出的公式，本项目将其实现为**可配置规则引擎**：

```
二手定价 = 图书定价 × 基础折扣系数 × 品相系数 × 供需系数 × 时效系数
```

| 系数 | 取值逻辑（引自计划书） | 数据来源表 |
|---|---|---|
| 基础折扣系数 | 按品类配置，默认 0.35~0.5（新书 3-5 折） | `pricing_rules` |
| 品相系数 | 9成新 0.55、8成新 0.45 … | `pricing_rules` |
| 供需系数 | 专业选课人数 ÷ 当前库存量 | `courses` + `listings` |
| 时效系数 | 随库存周转天数下调，触发阈值转入换书/捐赠通道 | `pricing_rules` |

> ⚠️ **数据真实性**：计划书中的系数与「试点验证」结论均为**示例数据**。
> 系统必须把系数做成**后台可配置**，并在界面上标注「测算参数，待真实数据校准」。

## 6. 碳减排测算

计划书 10.1 节（ISO 14040/14044 方法学）：

```
单册减排量 =（原生造纸与印刷碳排放 + 新书流通配送碳排放）
           −（二手回收消毒碳排放 + 二手履约配送碳排放）
```

| 参数 | 计划书示例值 | 状态 |
|---|---|---|
| 原生环节 | 1.05 kg CO₂e（300g 胶版纸教材） | **示例参数** |
| 二手履约环节 | 0.20 kg CO₂e | **示例参数** |
| 单册减排量 | 0.85 kg CO₂e | **示例参数** |

> ⚠️ 计划书原文特别说明：原稿「每本书减排 1.2kg」口径**须重新核验后方可使用**。
> 系统实现要求：
> 1. 系数存入数据库，**每个系数必须绑定来源字段**（`source_note`）；
> 2. 前端展示碳减排量时**必须同时展示「测算参数，非实测值」提示**；
> 3. 未填写来源的系数不允许对外展示。

## 8. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 目标接口延迟 50-100ms（国内云服务器 + 同区域数据库） |
| 兼容性 | 移动端优先（学生主要用手机浏览器）；适配微信内置浏览器 |
| 国际化 | 暂不需要，仅中文 |
| 可访问性 | 组件语义化、键盘可达、对比度达 WCAG AA |
| 离线容忍 | 弱网下关键操作给出明确提示，不静默失败 |
| 数据可移植 | 用户可导出个人数据、可注销账号（《个人信息保护法》第 45、47 条） |
